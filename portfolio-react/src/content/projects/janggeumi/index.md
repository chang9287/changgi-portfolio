# Overview

많은 사람들이 좋은 식재료를 고르는 기준이나 남은 식재료를 보관·활용하는 방법을 찾기 위해 여러 사이트와 영상을 찾아다녀야 합니다. 하지만 정보가 곳곳에 흩어져 있어 비교가 어렵고, 다양한 방법 중 어떤 것이 자신의 상황에 적합한지 판단하기도 쉽지 않습니다. 또한 정보의 신뢰성을 확인하기 어려워 잘못된 보관으로 식재료를 버리는 일이 반복되기도 합니다.

이러한 문제를 해결하기 위해 식재료의 구매부터 보관, 재사용, 처리까지 전 과정을 하나의 서비스에서 제공하는 '장금이'를 기획했습니다. 좋은 품질의 식재료를 고르는 기준과 상황별 보관 및 활용 방법을 제공하고, 실제 사용자들의 후기와 팁을 함께 축적하여 신뢰할 수 있는 정보를 제공하는 것을 목표로 했습니다.


# Problem & Solution

## Problem

식재료를 구매하거나 보관할 때 사용자는 블로그, 카페, 유튜브 등에 흩어진 정보를 하나씩 확인하고, 여러 콘텐츠에서 공통적으로 언급되는 방법을 직접 비교해야 했습니다.

콘텐츠마다 설명 방식과 기준이 달라 식재료의 상태에 적합한 방법을 판단하기 어려웠으며, 광고성 정보와 실제 경험을 구분하기도 쉽지 않았습니다. 구매 후에도 보관과 활용, 폐기 방법을 다시 검색해야 해 구매부터 처리까지 동일한 탐색과 검증 과정이 반복되고 있었습니다.

## Solution

구매·보관·처리로 나뉘어 있던 정보를 하나의 탐색 흐름으로 연결하고, 사용자가 식재료의 상태와 목적에 따라 필요한 정보를 확인할 수 있도록 구조화했습니다.

보관 단계에서는 식재료의 손질 상태와 보관 기간, 장소를 기준으로 적합한 방법을 탐색할 수 있도록 했으며, 처리 단계는 남은 재료의 활용과 폐기로 구분했습니다. 또한 구매·보관·처리 정보에 출처를 표시하고 사용자 후기와 댓글을 함께 제공해, 정보의 근거와 실제 적용 경험을 확인한 뒤 방법을 선택할 수 있도록 구성했습니다.

## Result

사용자는 여러 플랫폼을 반복해서 이동하지 않고, 구매 현장에서도 좋은 식재료를 고르는 기준과 정보의 출처를 함께 확인할 수 있도록 했습니다.

구매 후에는 식재료의 상태에 맞는 보관 방법부터 남은 재료의 활용과 폐기 방법까지 하나의 흐름 안에서 탐색할 수 있습니다. 또한 다른 사용자의 경험을 함께 비교할 수 있어, 단순히 가장 많이 언급된 방법을 따르기보다 정보의 근거와 자신의 상황을 바탕으로 적합한 방법을 판단할 수 있도록 했습니다.

따라서 Problem에서 제시한 정보의 분산, 비교의 어려움, 신뢰도 판단의 어려움, 단계마다 반복되는 검색이 Solution과 Result에서 모두 대응이 되었습니다.


# Main Feature

- 사용자 탐색 흐름을 고려한 메인 UI 구성

  식재료 검색이 사용자의 주요 행동이라고 판단해 메인 상단에 검색창을 배치하고, 검색한 식재료의 상세 페이지로 바로 이동하도록 구현했습니다. 이어서 서비스 캐릭터를 활용한 안내 영역에서는 별도의 검색 페이지로 이동할 수 있도록 했으며, 제철·인기 식재료와 최근 탐색한 식재료, 제철 안내 배너를 순서대로 구성해 검색부터 추천과 재탐색까지 자연스럽게 이어지도록 했습니다.

- 식재료별 구매 방법과 선택 기준 제공
- 손질 상태 · 보관 기간 · 보관 장소에 따른 보관 방법 제공
- 남은 식재료의 활용 레시피 및 올바른 폐기 방법 안내
- 출처 정보와 좋아요 · 댓글을 통한 사용자 경험 공유
- AI 스킬을 활용한 서비스 비주얼 제작

  캐릭터와 식재료 이미지가 서로 다른 스타일로 생성되지 않도록 이미지의 분위기와 표현 기준을 정의한 AI 스킬을 작성했습니다. 이를 활용해 서비스 캐릭터와 구매·보관·처리 단계에 필요한 식재료 이미지를 제작하고, 서비스 전반에서 일관된 비주얼이 유지되도록 적용했습니다.

- 로그인 및 사용자 진입 화면 구현
- 인증 상태에 따른 최근 본 식재료 관리

  비회원도 이전에 확인한 식재료를 다시 볼 수 있도록 최근 본 목록을 로컬 스토리지에 저장했습니다. 로그인하면 해당 계정의 목록을 불러오고, 로그아웃하면 다시 로컬 기록으로 전환해 인증 상태에 맞는 탐색 기록이 표시되도록 구현했습니다.



# What I Learned

이번 스프린트 프로젝트를 진행하며 Git을 사용할 줄 아는 것과, 팀이 Git을 통해 원활하게 협업하는 것은 다르다고 느꼈습니다. 팀원마다 브랜치와 커밋, PR을 사용하는 방식이 달랐고, API 수정 요청에서도 대상에 대한 이해가 엇갈려 작업이 반복되는 경험이 있었습니다. 이를 통해 작업을 시작하기 전에 브랜치 전략과 PR·병합 기준을 합의하고, 수정 요청에는 대상 엔드포인트와 변경 전후 상태, 기대 결과를 함께 전달해야 한다는 협업 기준을 갖게 되었습니다.

또한 AI를 단순한 이미지 생성 도구로 사용하는 데 그치지 않고, 일관된 결과를 얻기 위한 기준을 스킬로 작성해 캐릭터와 식재료 이미지 제작에 활용했습니다. 이번 경험을 통해 AI를 잘 활용한다는 것은 결과물을 빠르게 생성하는 것이 아니라, 원하는 방향을 구체적으로 정의하고 생성된 결과를 계속 판단하며 조정하는 과정이라고 생각하게 되었습니다.
